A reusable, typed viewer component

DocxViewer accepts a File, ArrayBuffer or Uint8Array and an optional signed licenseKey. Keep the source object stable until you intend to open another document. Use React for controls and status messages. Leave the host element empty for the SDK to fill.

DocxViewer.tsx · complete component
"use client";

import { useEffect, useRef, useState } from "react";
import type { BrowserDocument } from "@onodocs/sdk/browser";
import type { CanvasDocument } from "@onodocs/canvas";

export interface DocxViewerProps {
  source: File | ArrayBuffer | Uint8Array;
  licenseKey?: string;
}

export function DocxViewer({ source, licenseKey = "" }: DocxViewerProps) {
  const host = useRef<HTMLDivElement>(null);
  const cancel = useRef<() => void>(() => {});
  const [status, setStatus] = useState("Opening document…");
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const container = host.current!;
    const controller = new AbortController();
    const { signal } = controller;
    let doc: BrowserDocument | undefined;
    let canvasDocument: CanvasDocument | undefined;
    const stop = () => { controller.abort(); canvasDocument?.dispose(); doc?.dispose(); };
    cancel.current = () => {
      stop();
      setLoading(false);
      setStatus("Loading cancelled. Choose another file or open the sample.");
    };
    setLoading(true);
    setStatus("Opening document…");

    async function open() {
      try {
        const { openDocument } = await import("@onodocs/sdk/browser");
        const { createDocument } = await import("@onodocs/canvas");
        if (signal.aborted) return;
        doc = await openDocument(source, {
          signal,
          licenseKey,
          onProgress(progress) {
            if (signal.aborted) return;
            canvasDocument ??= createDocument(progress.document, { container, viewOptions: { zoom: "fit-width" } });
            const count = progress.document.pages.length;
            setStatus(count ? `Loading… ${count} ${count === 1 ? "page" : "pages"} available` : `Loading: ${progress.stage}…`);
          }
        });
        if (signal.aborted) { doc.dispose(); return; }
        await canvasDocument!.view!.whenRendered();
        if (!signal.aborted) setStatus(`Ready · ${doc.pages.length} ${doc.pages.length === 1 ? "page" : "pages"}. Select text to copy it.`);
      } catch (error) {
        canvasDocument?.dispose();
        doc?.dispose();
        if (!signal.aborted) setStatus(`Unable to open document. ${error instanceof Error ? error.message : "Try another Word file."}`);
      } finally {
        if (!signal.aborted) setLoading(false);
      }
    }

    void open();
    return stop;
  }, [source, licenseKey]);

  return <section className="docx-viewer" aria-label="Word viewer">
    <div className="viewer-status"><output aria-live="polite">{status}</output><button type="button" disabled={!loading} onClick={() => cancel.current()}>Cancel loading</button></div>
    <div className="viewer-viewport"><div ref={host} /></div>
  </section>;
}

The effect imports the browser SDK only after mounting. Opening receives an abort signal and a container, so provisional pages can appear during layout. The ready state waits for whenRendered() to finish painting the current viewport. Other pages paint as you scroll. Use this component with the CSS below.

Connect a file picker and sample document

The application stores the selected file in state and passes it to the viewer. The sample button supplies a fresh byte array to reopen the built-in document even after cancellation. Hide viewer unmounts the component; Show viewer mounts it again.

Handle replacement, cancellation and unmounting

Each effect invocation creates a separate abort controller and keeps references to its preview view and completed document. When source or licenseKey changes, cleanup aborts the previous operation and releases its resources. Cleanup also runs on unmount. A document that completes after cancellation is disposed immediately, and aborted operations cannot overwrite the current status.

The Cancel button uses that same cleanup function and leaves the controls available for another file. A rejected load displays an error and releases any preview. The user can then choose another document.

Progress reports stages and available pages, not a percentage. Early page boundaries can change as layout settles. The completed viewer retains canvases near the viewport, but the document model still consumes memory proportional to the content. Mobile devices can take longer to open large documents.

Keep React Strict Mode enabled

React runs an extra effect setup and cleanup cycle in development when Strict Mode is enabled. Each effect invocation has its own abort controller, so cleanup cancels only that invocation’s load. A “run once” ref that suppresses the second setup can leave the viewer empty after cleanup.

The public sample wraps its root in StrictMode. The local development build runs this extra cycle. The production demo uses React's production build. See React's documentation for effect dependencies and cleanup and Strict Mode.

Local processing, evaluation and commercial use

Selected documents are parsed, laid out and rendered in the browser. This sample does not upload contents or filenames, send analytics, or call an AI service. Loading the app still downloads JavaScript and CSS. Remote documents and fonts require separate requests. Cache all required assets if your application must work offline.

Evaluation is registration-free and adds a watermark. Supply an issued signed token through licenseKey for a trial or licensed application. Verification happens offline. The license key issued by OnoDocs can be included in your application bundle. Browser verification requires HTTPS or localhost. Sample code and authored documents are MIT-licensed. The SDK has separate license terms.

Common React integration problems

The document keeps reopening
Do not create a new source byte array in every render. Store it in state, keep a module-level sample, or memoize it from stable inputs. The effect reloads whenever its source identity or license changes.
The viewer is blank or cannot scroll
Give its parent a height and allow the viewport to shrink with min-height: 0. Keep the SDK host empty in your JSX; do not render React children into it.
The layout differs from Word
Check the document's fonts. See font setup and deployment. Rendering can differ from Word. Report differences with minimal fictional examples in GitHub Issues.
A file fails to load
Supported packages include DOCX, DOCM, DOTX and DOTM. Macros are not executed. Password-protected documents and older DOC or RTF files need to be unlocked or converted first. General Word editing and saving changes back to DOCX are not supported.
