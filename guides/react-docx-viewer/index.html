Build a React Word document viewer with TypeScript

Embed DOCX pages in a React application with a reusable, typed component. Open local files, show loading progress, select and copy text, and clean up when the document changes or the component unmounts.

Run the React and TypeScript sample

Install Node.js 22.18 or newer and npm. Clone the public OnoDocs repository, or download the source ZIP.

git clone https://github.com/onodocs/onodocs.git
cd onodocs
npm run setup
npm start

Open http://127.0.0.1:5174/react-docx-viewer/. Setup downloads the pinned SDK archive from the public release and installs React, React DOM and TypeScript dependencies. No GitHub sign-in or licence key is required for evaluation. Run npm run typecheck and npm run build to check and bundle the samples.

For an existing React project, download SDK 0.2.0-beta.3, then install the archive:

npm install ./onodocs-sdk-0.2.0-beta.3.tgz

The SDK is distributed through GitHub releases during preview. It is not published to public npm. Its TypeScript declarations are included; no separate SDK types package is needed. Use your project's existing React dependencies and bundler. The supplied sample uses React 19.3 and the automatic JSX transform.

A reusable, typed viewer component

DocxViewer accepts a File, ArrayBuffer or Uint8Array and an optional signed licenseKey. Keep the source object stable until you intend to open another document. React owns the controls and status; the SDK owns the contents of the empty host element.

DocxViewer.tsx · complete component
"use client";

import { useEffect, useRef, useState } from "react";
import type { BrowserDocument, DocumentView } from "@onodocs/sdk/browser";

export interface DocxViewerProps {
  source: File | ArrayBuffer | Uint8Array;
  licenseKey?: string;
}

export function DocxViewer({ source, licenseKey = "" }: DocxViewerProps) {
  const host = useRef<HTMLDivElement>(null);
  const cancel = useRef<() => void>(() => {});
  const [status, setStatus] = useState("Opening document…");
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const container = host.current!;
    const controller = new AbortController();
    const { signal } = controller;
    let doc: BrowserDocument | undefined;
    let view: DocumentView | undefined;
    const stop = () => { controller.abort(); view?.dispose(); doc?.dispose(); };
    cancel.current = () => {
      stop();
      setLoading(false);
      setStatus("Loading cancelled. Choose another file or open the sample.");
    };
    setLoading(true);
    setStatus("Opening document…");

    async function open() {
      try {
        const { openDocument } = await import("@onodocs/sdk/browser");
        if (signal.aborted) return;
        doc = await openDocument(source, {
          container,
          signal,
          licenseKey,
          viewOptions: { zoom: "fit-width" },
          onProgress(progress) {
            if (signal.aborted) return;
            view = progress.view;
            setStatus(progress.pages.length ? `Loading… ${progress.pages.length} pages available` : `Loading: ${progress.stage}…`);
          }
        });
        if (signal.aborted) { doc.dispose(); return; }
        view = doc.view;
        await view!.whenRendered();
        if (!signal.aborted) setStatus(`Ready · ${doc.pages.length} ${doc.pages.length === 1 ? "page" : "pages"}. Select text to copy it.`);
      } catch (error) {
        view?.dispose();
        doc?.dispose();
        if (!signal.aborted) setStatus(`Unable to open document. ${error instanceof Error ? error.message : "Try another Word file."}`);
      } finally {
        if (!signal.aborted) setLoading(false);
      }
    }

    void open();
    return stop;
  }, [source, licenseKey]);

  return <section className="docx-viewer" aria-label="Word viewer">
    <div className="viewer-status"><output aria-live="polite">{status}</output><button type="button" disabled={!loading} onClick={() => cancel.current()}>Cancel loading</button></div>
    <div className="viewer-viewport"><div ref={host} /></div>
  </section>;
}

The effect imports the browser SDK only after mounting. Opening receives an abort signal and a container, so provisional pages can appear during layout. The ready state waits for whenRendered(), which paints the current viewport; other pages paint as you scroll. Use this component with the CSS below.

Connect a file picker and sample document

The application stores the selected file in state and passes it to the viewer. The sample button supplies a fresh byte array to reopen the built-in document even after cancellation. Hide viewer unmounts the component; Show viewer mounts it again.

App.tsx · file picker and lifecycle controls
"use client";

import { useState } from "react";
import { DocxViewer } from "./DocxViewer";
import sample from "../view-document/sample.docx";

export function App() {
  const [source, setSource] = useState<File | Uint8Array>(sample);
  const [visible, setVisible] = useState(true);

  return <>
    <header>
      <label>Open Word file <input type="file" accept=".docx,.docm,.dotx,.dotm" onChange={event => {
        const file = event.currentTarget.files?.[0];
        event.currentTarget.value = "";
        if (file) { setSource(file); setVisible(true); }
      }} /></label>
      <button type="button" onClick={() => { setSource(sample.slice()); setVisible(true); }}>Open sample</button>
      <button type="button" onClick={() => setVisible(value => !value)}>{visible ? "Hide viewer" : "Show viewer"}</button>
      <a href="https://github.com/onodocs/onodocs/tree/main/examples/react-docx-viewer" target="_blank" rel="noopener">Source on GitHub</a>
    </header>
    {visible ? <DocxViewer source={source} /> : <p className="closed-message">Viewer closed. Show it again to reopen the document.</p>}
  </>;
}

Handle replacement, cancellation and unmounting

Every effect invocation owns its own abort controller, preview view and completed document. When source or licenseKey changes, cleanup aborts the previous operation and releases its resources. Cleanup also runs on unmount. A document that completes after cancellation is disposed immediately, and aborted operations cannot overwrite the current status.

The Cancel button uses that same cleanup function and leaves the controls available for another file. A rejected load displays an error and releases any preview. The application can recover by choosing another document.

Progress reports stages and available pages, not a percentage. Early page boundaries can change as layout settles. The completed viewer retains canvases near the viewport, but the document model still consumes memory proportional to the content. Mobile devices can take longer to open large documents.

Keep React Strict Mode enabled

React runs an extra effect setup and cleanup cycle in development when Strict Mode is enabled. Each load here has an independent lifetime, so the first cleanup can cancel its own work without cancelling the next opening. Avoid a “run once” ref that suppresses the second setup: it can leave the viewer empty after cleanup.

The public sample wraps its root in StrictMode. The local development build exercises this extra cycle; the production demo uses React's production build. See React's documentation for effect dependencies and cleanup and Strict Mode.

Use the component in Next.js

The component already begins with "use client". It uses a type-only SDK import at module scope and imports the browser implementation inside the effect, which runs after mounting. This allows the initial component markup to be rendered on the server while document rendering stays in the browser.

Copy DocxViewer.tsx into app/components/ and add the sample's viewer styles to your application stylesheet. Give the wrapper a usable height. A file-picker page can look like this:

"use client";

import { useState } from "react";
import { DocxViewer } from "./components/DocxViewer";

export default function Page() {
  const [file, setFile] = useState<File | null>(null);
  return <main>
    <label>Open Word file <input type="file" accept=".docx,.docm,.dotx,.dotm"
      onChange={event => {
        const selected = event.currentTarget.files?.[0];
        event.currentTarget.value = "";
        if (selected) setFile(selected);
      }} /></label>
    <div style={{ height: "75vh", display: "flex", flexDirection: "column" }}>
      {file && <DocxViewer source={file} />}
    </div>
  </main>;
}

Keep browser File values in client state. For a remote document, fetch its authorized URL in client code, check response.ok, and pass the bytes. Cancel that fetch separately when its source changes. Access control and CORS belong to your application; a client component does not make protected documents public.

No next/dynamic wrapper is required for this component. If your own wrapper depends on browser APIs during module evaluation, Next.js supports disabling its server rendering with ssr: false from a Client Component. See Next.js lazy-loading guidance.

Local processing, evaluation and commercial use

Selected documents are parsed, laid out and rendered in the browser. This sample does not upload contents or filenames, send analytics, or call an AI service. Loading the app still downloads JavaScript and CSS. Configured remote documents or font URLs can require their own requests; cache all required assets if your application must work offline.

Evaluation is registration-free and adds a watermark. Supply an issued signed token through licenseKey for a trial or licensed application. Verification happens offline. A signed token can be included in client code; the private signing key must remain with the issuer. Sample code and authored documents are MIT-licensed; the SDK has separate licence terms.

Common React integration problems

The document keeps reopening
Do not create a new source byte array in every render. Store it in state, keep a module-level sample, or memoize it from stable inputs. The effect reloads whenever its source identity or licence changes.
The viewer is blank or cannot scroll
Give its parent a height and allow the viewport to shrink with min-height: 0. Keep the SDK host empty in your JSX; do not render React children into it.
The layout differs from Word
Check the document's fonts. See font setup and deployment. Exact parity with every Word feature is not guaranteed; share minimal fictional examples in GitHub Issues.
A file fails to load
Supported packages include DOCX, DOCM, DOTX and DOTM. VBA does not execute. Password-protected documents and older DOC or RTF files need to be unlocked or converted first. General Word editing and DOCX round-trip saving are not supported.
