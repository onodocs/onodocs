Extract text and tables from DOCX in JavaScript and TypeScript

Turn Word content into plain text and JSON for search, application records or AI input. Use the same typed query API in the browser and Node.js, without rendering pages or starting a headless browser.

Try DOCX-to-text and DOCX-to-JSON extraction

The included project brief has two tables. Choose Body text, All body tables, or Delivery records. Open your own Word file to use the same queries, then copy or download the result. The delivery query returns an empty array when a document has no matching table.

Open the extraction demo in a full tab. Selected files are processed locally; this demo does not upload them or call an AI service.

Run the JavaScript or TypeScript sample

Install Node.js 22.18 or newer and npm, then clone the public OnoDocs repository or download the source ZIP.

git clone https://github.com/onodocs/onodocs.git
cd onodocs
npm run setup
npm start

Open http://127.0.0.1:5174/docx-extraction/ for TypeScript or http://127.0.0.1:5174/javascript-extraction/ for JavaScript. Both use the same extraction logic. Setup downloads the pinned evaluation SDK from the public release. No GitHub sign-in or licence key is required. Run npm run typecheck and npm run build to check and bundle the examples.

For an existing application, download SDK 0.2.0-beta.3 and install the archive:

npm install ./onodocs-sdk-0.2.0-beta.3.tgz

During preview the SDK is distributed as a GitHub release archive, not a public npm package. TypeScript declarations are included. Use the analysis entry point @onodocs/sdk; the /browser entry point is for page rendering.

Read plain text and typed paragraphs

Open a browser File, an ArrayBuffer or a Uint8Array. The resulting inspected document exposes semantic queries and needs no canvas, fonts or page layout.

import { openDocument } from "@onodocs/sdk";

const doc = await openDocument(file);
const body = doc.query.stories().where({ story: "body" });
const text = body.map(story => story.text).join("\n");
const paragraphs = body.paragraphs().map(paragraph => ({
  text: paragraph.text,
  style: paragraph.style
}));

file is the selected browser File; the complete file picker appears below. Paragraph text joins its runs, so formatting changes do not split a sentence into separate records. Paragraph queries include paragraphs inside tables and content controls. Body text already includes table-cell text: appending the tables again would duplicate that content. Plain text preserves imported text and paragraph boundaries, not the page layout.

Extract tables as arrays of rows and cells

const tables = body.tables().map(table => table.textRows);

The result is an array of tables; each table contains rows, and each row contains cell strings. textRows includes the first row. It does not guess whether that row contains headers or convert dates, numbers or currencies. This keeps the source text available before application-specific interpretation.

For structural access, use table.rows, row.cells and each cell's children. A merged or nested table is not necessarily a rectangular spreadsheet. textRows lists the imported cells; it does not expand merged spans into repeated values. Nested table text can occur inside an outer cell, while tables() also returns nested tables. Choose the level your application needs before flattening.

Find a table by its headers and map rows to JSON

The sample brief uses the first-row labels Deliverable, Owner and Due. Match those labels in their exact order, then remove the header row and map the remaining cells:

const matches = body.tables().where({
  headers: ["Deliverable", "Owner", "Due"]
});
const deliveryTables = matches.map(table =>
  table.textRows.slice(1).map(([deliverable = "", owner = "", due = ""]) => ({
    deliverable, owner, due
  }))
);

Header matching compares the complete first row, including case and whitespace. It does not search later rows or infer synonyms. The output keeps matching tables separate: zero matches gives [], and multiple matches remain available. Use one() only when exactly one match is required; it throws for zero or multiple results. optional() allows zero but still throws for multiple matches.

This record mapping is for the simple three-column sample. Missing cells become empty strings; additional cells remain available in the raw table output. Validate required values, merged cells and date formats in your application before importing records. Here a due date remains the authored text, such as “Nov 04”, rather than an invented calendar date.

The complete browser extraction sample

The reusable function below supplies the browser and Node.js samples. It projects SDK objects into JSON-safe values. Avoid serializing the full query objects: they contain parent links and source metadata, not a portable data-transfer format.

extract.ts · typed extraction function
import type { InspectedDocument } from "@onodocs/sdk";

export function extractContent(doc: InspectedDocument) {
  const body = doc.query.stories().where({ story: "body" });
  const tables = body.tables();
  return {
    text: body.map(story => story.text).join("\n"),
    paragraphs: body.paragraphs().map(paragraph => ({ text: paragraph.text, style: paragraph.style })),
    tables: tables.map(table => table.textRows),
    deliveryTables: tables.where({ headers: ["Deliverable", "Owner", "Due"] }).map(table =>
      table.textRows.slice(1).map(([deliverable = "", owner = "", due = ""]) => ({ deliverable, owner, due }))
    )
  };
}
extract.js · plain JavaScript equivalent
function extractContent(doc) {

  const tables = body.tables();
  return {
    text: body.map((story) => story.text).join("\n"),
    paragraphs: body.paragraphs().map((paragraph) => ({ text: paragraph.text, style: paragraph.style })),

main.ts · local files, cancellation, copy and download
import { openDocument } from "@onodocs/sdk";
import { extractContent } from "./extract.ts";
import sample from "../view-document/sample.docx";

const status = document.querySelector<HTMLOutputElement>("#status")!;
const file = document.querySelector<HTMLInputElement>("#file")!;
const format = document.querySelector<HTMLSelectElement>("#format")!;
const output = document.querySelector<HTMLTextAreaElement>("#output")!;
const cancel = document.querySelector<HTMLButtonElement>("#cancel")!;
const copy = document.querySelector<HTMLButtonElement>("#copy")!;
const download = document.querySelector<HTMLButtonElement>("#download")!;
let controller: AbortController | undefined;
let content: ReturnType<typeof extractContent> | undefined;

function showOutput() {
  output.value = !content ? "" : format.value === "text" ? content.text : JSON.stringify(format.value === "tables" ? content.tables : content.deliveryTables, null, 2);
}

async function open(source: File | Uint8Array) {
  controller?.abort();
  controller = new AbortController();
  const { signal } = controller;
  content = undefined;
  showOutput();
  copy.disabled = download.disabled = true;
  cancel.disabled = false;
  status.textContent = "Extracting document…";
  try {
    const doc = await openDocument(source, { signal });
    if (signal.aborted) return;
    content = extractContent(doc);
    showOutput();
    copy.disabled = download.disabled = false;
    status.textContent = `Ready · ${content.paragraphs.length} body paragraphs · ${content.tables.length} tables · ${content.deliveryTables.length} delivery tables. Everything stays in this browser.`;
  } catch (error) {
    if (!signal.aborted) status.textContent = `Unable to extract document. ${error instanceof Error ? error.message : "Try another Word file."}`;
  } finally {
    if (!signal.aborted) cancel.disabled = true;
  }
}

file.addEventListener("change", () => {
  const selected = file.files?.[0];
  file.value = "";
  if (selected) void open(selected);
});
document.querySelector("#sample")!.addEventListener("click", () => { void open(sample); });
format.addEventListener("change", showOutput);
cancel.addEventListener("click", () => {
  controller?.abort();
  cancel.disabled = true;
  status.textContent = "Extraction cancelled. Choose another file or open the sample.";
});
copy.addEventListener("click", async () => {
  try {
    await navigator.clipboard.writeText(output.value);
    status.textContent = "Output copied.";
  } catch {
    output.focus();
    output.select();
    status.textContent = "Copy unavailable. The output is selected; use Ctrl+C or Command+C.";
  }
});
download.addEventListener("click", () => {
  const plain = format.value === "text";
  const url = URL.createObjectURL(new Blob([output.value], { type: plain ? "text/plain;charset=utf-8" : "application/json" }));
  const link = document.createElement("a");
  link.href = url;
  link.download = plain ? "document-text.txt" : `${format.value}.json`;
  link.click();
  setTimeout(() => URL.revokeObjectURL(url), 1000);
});
window.addEventListener("pagehide", event => { if (!event.persisted) { controller?.abort(); content = undefined; } });
void open(sample);

The build embeds ../view-document/sample.docx using its DOCX binary loader. Copy the repository to run the exact example; an application that only opens local files needs no DOCX loader. Opening a replacement aborts the previous operation and clears its output. Failed loads leave copy/download disabled until another document succeeds.

Unlike the rendering document, this inspected document has no dispose() method. Release references when finished; there are no views or page canvases to dispose. Cancellation uses AbortSignal and does not promise an instantaneous interruption of every synchronous step. Large document models and JSON output still take memory and processing time.

Extract DOCX content in Node.js without a browser

The same analysis entry point accepts a Node Buffer, which is a Uint8Array. This CLI uses the same extraction function and writes JSON to standard output. Its source link goes to standard error, keeping redirected JSON valid.

node.ts · complete Node.js command
import { readFile } from "node:fs/promises";
import { openDocument } from "@onodocs/sdk";
import { extractContent } from "./extract.ts";

const bytes = await readFile(process.argv[2] ?? new URL("../view-document/sample.docx", import.meta.url));
const doc = await openDocument(bytes);
console.log(JSON.stringify(extractContent(doc), null, 2));
console.error("Sample source: https://github.com/onodocs/onodocs/tree/main/examples/docx-extraction");

Scope stories and search paragraph text

Body, headers, footers, notes and textboxes are separate stories. Query them deliberately when defining the contents of an export. A header story is authored content, not a separate copy for every rendered page.

const headers = doc.query.stories().where({ story: "header" })
  .paragraphs().map(paragraph => paragraph.text);

const matches = body.findText(/launch/gi).map(range => ({
  text: range.text,
  paragraph: range.paragraph.text,
  start: range.start,
  end: range.end
}));

Search returns paragraph-local ranges and can span formatting runs within one paragraph, but not paragraph boundaries. Offsets follow JavaScript UTF-16 string indexing and the end offset is exclusive. See the query API, element types, and text ranges.

Extraction limits, privacy and licensing

This is extraction of supported Word content, not OCR. Text that exists only inside an image is not recognized. The output is a semantic projection, not lossless OOXML or a reconstruction of Word's visual reading order; floating objects and page columns need particular care. Text extraction does not preserve styling, exact pagination, or recalculate every Word field.

Supported packages include DOCX, DOCM, DOTX and DOTM. VBA does not execute. Password-protected files and older DOC, DOT or RTF files must be unlocked or converted first. General Word editing and DOCX round-trip saving are not supported.

The browser sample does not send document contents, filenames, extracted values or analytics. Initial loading downloads application assets; local extraction, copying and downloading require no server. Nothing is sent to an AI model. If your application later sends extracted content elsewhere, that is a separate data-handling decision.

Evaluation is registration-free and exposes the complete query API. The rendering watermark does not get inserted into extracted text. Commercial use still requires the appropriate SDK licence; signed keys are verified offline. Sample code, guides and authored documents are MIT-licensed, while the SDK is separately licensed.
