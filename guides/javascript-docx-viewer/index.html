Build a DOCX viewer in JavaScript and TypeScript

Open a Word document inside your application, render its pages, and let users select and copy text. This example processes local files in the browser and needs no document-processing backend.

Try the viewer

Choose a local Word file, or use the included project brief. Drag across text to select it. The sample uses unrestricted evaluation mode and displays the SDK watermark.

Open the viewer in a full tab. The live example and the source below use the same implementation.

Run the JavaScript or TypeScript sample locally

You need Node.js 22.18 or newer and npm. Clone the public OnoDocs repository, or download its ZIP and extract it.

git clone https://github.com/onodocs/onodocs.git
cd onodocs
npm run setup
npm start

Open http://127.0.0.1:5174/samples.html and choose the JavaScript or TypeScript DOCX viewer. Setup downloads the pinned SDK release and installs dependencies. No GitHub account, registration or licence key is needed for evaluation.

The sample folder contains main.ts, its JavaScript equivalent main.js, HTML and CSS. Both language versions run through the included build script. TypeScript declarations ship with @onodocs/sdk; a separate types package is unnecessary.

For an existing application, download the SDK release archive and install the local file:

npm install ./onodocs-sdk-0.2.0-beta.3.tgz

Use your application's bundler and import @onodocs/sdk/browser. The SDK is distributed through GitHub releases during preview; it is not published to public npm. Sample code and authored documents are MIT-licensed. The SDK has separate evaluation and commercial terms.

Render your first DOCX file

Give the SDK a DOM container and a File, ArrayBuffer or Uint8Array. For example, inside your file-picker handler:

import { openDocument } from "@onodocs/sdk/browser";

const doc = await openDocument(file, {
  container: document.querySelector("#pages"),
  viewOptions: { zoom: "fit-width" }
});
await doc.view.whenRendered();

This short snippet shows the rendering call. The complete example below also handles errors, replacement, cancellation and disposal. In TypeScript, use document.querySelector<HTMLElement>("#pages")! when your HTML guarantees that the container exists.

For documents served by your application, fetch the authorized URL and pass its bytes. Check response.ok, forward the cancellation signal to fetch, and retain your application's access controls. See the shared mount helper for that version.

Complete source: TypeScript and JavaScript

The example embeds the supplied Word sample at build time. Local files selected afterward are passed directly to the SDK. Copy the folder and its ../view-document/sample.docx dependency, or run the complete repository.

TypeScript · main.ts
import { openDocument, type BrowserDocument, type DocumentView } from "@onodocs/sdk/browser";
import sample from "../view-document/sample.docx";

const pages = document.querySelector<HTMLElement>("#pages")!;
const status = document.querySelector<HTMLOutputElement>("#status")!;
const file = document.querySelector<HTMLInputElement>("#file")!;
const cancel = document.querySelector<HTMLButtonElement>("#cancel")!;
let stop = () => {};

async function open(source: File | Uint8Array) {
  stop();
  const controller = new AbortController();
  const { signal } = controller;
  let doc: BrowserDocument | undefined;
  let view: DocumentView | undefined;
  stop = () => { controller.abort(); view?.dispose(); doc?.dispose(); };
  status.textContent = "Opening document…";
  cancel.disabled = false;
  try {
    doc = await openDocument(source, {
      container: pages,
      signal,
      viewOptions: { zoom: "fit-width" },
      onProgress(progress) {
        if (signal.aborted) return;
        view = progress.view;
        status.textContent = progress.pages.length ? `Loading… ${progress.pages.length} pages available` : `Loading: ${progress.stage}…`;
      }
    });
    if (signal.aborted) { doc.dispose(); return; }
    view = doc.view;
    await view!.whenRendered();
    if (!signal.aborted) status.textContent = `Ready · ${doc.pages.length} ${doc.pages.length === 1 ? "page" : "pages"}. Select text to copy it.`;
  } catch (error) {
    view?.dispose();
    doc?.dispose();
    if (!signal.aborted) status.textContent = `Unable to open document. ${error instanceof Error ? error.message : "Try another Word file."}`;
  } finally {
    if (!signal.aborted) cancel.disabled = true;
  }
}

file.addEventListener("change", () => {
  const selected = file.files?.[0];
  file.value = "";
  if (selected) void open(selected);
});
document.querySelector("#sample")!.addEventListener("click", () => { void open(sample); });
cancel.addEventListener("click", () => {
  stop();
  cancel.disabled = true;
  status.textContent = "Loading cancelled. Choose another file or open the sample.";
});
window.addEventListener("pagehide", event => { if (!event.persisted) stop(); });
void open(sample);

Handle loading, cancellation and cleanup

Passing container allows early pages to appear while the remaining document is laid out. onProgress reports the current stage and available pages. That count is provisional: pagination can change before opening finishes, so the example does not present it as a completion percentage.

Each opening operation owns an AbortController. Choosing another file aborts the previous operation and disposes its preview view and completed document. The signal checks prevent an older operation from overwriting the new status. The Cancel button uses the same cleanup path.

The completed view paints nearby pages as you scroll. This reduces retained canvases; parsing and the document model still require memory. Large or complex files can therefore take longer, especially on mobile devices.

Call cleanup when removing the viewer. The standalone sample uses pagehide; React, Vue and other frameworks should use their component lifecycle. Use the complete React and TypeScript viewer guide, or see the other framework integration examples.

Select and copy text

The SDK view supplies text selection. Drag through the document, or focus it and use Shift with the arrow keys. Use Ctrl+C on Windows and Linux or Command+C on macOS to copy. Selection can span pages and survives virtualized scrolling. Application controls such as the file picker keep their normal keyboard behavior.

The document is a rendered viewer. Text selection does not turn it into a general Word editor. Our text-update APIs support template workflows; DOCX round-trip saving is not available.

Match the document's fonts

Fonts influence line wrapping, page count and visual fidelity. Embedded document fonts load automatically. For additional fonts, provide browser-accessible font URLs through the SDK's fonts option and ensure you have permission to distribute them. See fonts and deployment.

Compare your representative documents using the same fonts. The renderer supports Word documents, but exact parity for every Word feature and document is not guaranteed. Older binary .doc files and RTF are unsupported; convert them to DOCX before loading.

Preview documents without uploading them

The file picker supplies a browser File. The sample performs parsing, layout and rendering on the device; it does not upload file contents or filenames, send analytics, or call an AI service. The bundled example document also needs no document download after the application has loaded.

Loading the webpage still downloads scripts and styles. Your application may separately fetch documents or fonts from URLs you configure. For offline use, serve or cache all required assets locally. Commercial licence signatures are verified locally; they require no licence-server request.

Common integration problems

Nothing appears
Run the sample through its HTTP server, verify that #pages exists, and give the scrolling area a usable height. An HTML file opened directly from disk is not the supported setup.
A local file will not open
Check that it is a supported Word package. Password-protected documents and old .doc files need to be converted or unlocked first. The UI should keep the error visible and allow another file.
Remote loading fails
Check your HTTP response, authentication and CORS configuration. These belong to the application that retrieves the bytes.
The layout differs from Word
Check fonts first, then test a minimal document. Report reproducible differences with the SDK version and a non-confidential sample through GitHub Issues.
